# StudyStack

Djangoで作成した学習記録アプリです。

ユーザーごとに学習内容を登録・編集・削除できます。

## 主な機能

- ユーザー登録
- ログイン / ログアウト
- 学習記録の登録
- 学習記録の一覧表示
- 学習記録の編集
- 学習記録の削除
- ユーザーごとのデータ分離
- 入力バリデーション
- ログイン必須ページのアクセス制御
- 他ユーザーの学習記録への編集・削除防止

## 使用技術

- Python
- Django
- HTML
- CSS
- JavaScript
- SQLite

## 実装で学んだこと

### DjangoのCRUD

Create / Read / Update / Delete の基本的な流れを実装しました。

特にUpdateでは、URLから取得した `study_id` とログイン中の
`request.user` を利用し、対象ユーザーの学習記録だけを取得・更新する仕組みを学びました。

### ModelFormとバリデーション

`StudyForm` をCreateとUpdateの両方で使用し、
フォーム側に入力チェックの責務を持たせました。

独自バリデーションとして、

- 空白のみの入力を禁止
- 3文字以下の入力を禁止

を実装しました。

### 認証とユーザーごとのデータ管理

`@login_required` を使用して、
ログインしているユーザーだけがダッシュボードへアクセスできるようにしました。

また、Study取得時にログインユーザーを条件へ含めることで、
他ユーザーの学習記録を編集・削除できないようにしています。

対象データが存在しない場合や、他ユーザーのデータへアクセスした場合には
`get_object_or_404()` を使用し、404レスポンスとして処理するよう改善しました。

### URL / View / Template の役割

DjangoではHTMLファイルへ直接遷移するのではなく、

URL → View → Template

という流れで画面を表示することを学びました。

また、`reverse()` を利用し、
URLを直接記述するのではなくURL名から取得する方法も学びました。

### POST処理

登録・更新・削除・ログアウトなど、
状態を変更する処理ではPOSTを使用しました。

削除時にはJavaScriptの `confirm()` を使用し、
誤操作防止の確認ダイアログも追加しました。

## テスト

Djangoの `TestCase` を使用し、19件のテストを作成しました。

### Formテスト

- 正常な学習内容がバリデーションを通過すること
- 短すぎる入力が拒否されること
- 空白のみの入力が拒否されること

### Modelテスト

- Studyの作成
- Studyの取得
- Studyの更新
- Studyの削除
- StudyとUserが正しく紐づくこと

### 認証・Viewテスト

- 正しい認証情報でログインできること
- 間違った認証情報ではログインできないこと
- 未ログインユーザーがDashboardへアクセスできないこと
- Signupの成功 / 失敗
- Logout後に認証必須ページへアクセスできないこと

### アクセス制御・CRUDテスト

- ログインユーザーには自分のStudyだけが表示されること
- 他ユーザーのStudyは表示されないこと
- 他ユーザーのStudyを更新できないこと
- 他ユーザーのStudyを削除できないこと
- Dashboardから作成したStudyがログインユーザーへ正しく紐づくこと
- 自分のStudyを更新できること
- 自分のStudyを削除できること
